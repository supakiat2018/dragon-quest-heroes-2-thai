# โครงสร้างตารางข้อความและระบบ Pointer (Koei Tecmo Text Format)

## 1. กฎการคำนวณตำแหน่ง Pointer
ในไฟล์ข้อความอย่าง `entry_204.bin`:
* ตาราง Pointer เริ่มต้นที่ Offset `0x20`
* ตัวชี้ `Pointer (P)` มีขนาด 4 bytes (uint32 Little-Endian)
* **สูตรหาตำแหน่งข้อความจริงในไฟล์:**
  $$\text{ตำแหน่งข้อความในไฟล์} = \text{0x20} + P$$
* หรือกลับกัน:
  $$P = \text{ตำแหน่งข้อความในไฟล์} - \text{0x20}$$

## 2. วิธีการแก้ข้อความ: เขียนต่อท้ายและชี้ Pointer ไป (Append & Repoint)

### ทำไมถึงต้องใช้วิธีนี้?
* หากแทนที่ข้อความเดิมตรงๆ แต่ข้อความใหม่ยาวกว่าเดิม (เช่น `Exit Game` มี 9 ตัวอักษร แต่ต้องการเปลี่ยนเป็น 18 ตัวอักษร) การเขียนทับตรงๆ จะไป**ทับข้อความถัดไป** (`Full Screen Display`) จนพัง
* แต่หากใช้วิธี **เขียนต่อท้ายลงในพื้นที่ว่างท้ายไฟล์ (Trailing Zeros)** แล้วนำค่าตำแหน่งใหม่มาแก้ตัวชี้ในตาราง Pointer:
  1. ข้อความเดิมยังอยู่ หรือกลายเป็นขยะที่ไม่ถูกเรียกใช้ ไม่พัง
  2. ข้อความใหม่แสดงผลได้เต็มความยาว
  3. Pointer ตัวอื่นๆ ไม่ต้องเลื่อนตำแหน่งตาม
  4. ขนาดไฟล์รวมไม่เปลี่ยน (ยังเท่าเดิม 86,768 bytes)

### ตัวอย่างจริงที่ทดสอบ:
* ข้อความเดิม: `Exit Game\0` (อยู่ที่ Offset `83735`)
* Pointer เดิมอยู่ที่ Offset `6808` (`0x1a98`): ชี้ไปที่ `83703` ($83735 - 32$)
* นำ `xxxxxxxxxxxxxxxxxx\0` ไปเขียนที่ Offset ท้ายไฟล์ `86672`
* อัปเดต Pointer ที่ Offset `6808` เป็น `86640` ($86672 - 32$)
* เกมจะอ่านข้อความใหม่ที่ยาว 18 ตัวอักษรได้ทันทีโดยไม่ชนกับข้อความอื่น
